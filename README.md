# Jev SEO Radar

Микроплатформа, която анализира конкурентите ти в Google по ключова дума. Въвеждаш фраза (например „изработка на уебсайт“) и получаваш: кои сайтове са начело, какви са силните и слабите им страни, по кои свързани фрази можеш да се класираш бързо, ако напишеш качествено съдържание, и конкретен план какво да напишеш.

Работи на твоя компютър или сървър. Решенията за съдържанието взема **Jev** на [TypeSafe AI](https://typesafe.ai); ключът му стои във файл `.env` и никога не стига до браузъра.

## Какво получаваш

| Раздел на отчета | Какво показва |
| --- | --- |
| **Преглед** | какво показва Google за фразата (тип страници, намерение), кой доминира, най-добрите възможности, първи стъпки |
| **Топ резултати** | всеки водещ резултат с оценки за съдържание, оптимизация, доверие и конверсия; отваря се за пълния списък със силни и слаби страни |
| **Възможности** | карта „колко е слаба конкуренцията × колко струва фразата“ и таблица с всички свързани фрази, всяка с обяснение защо е възможност |
| **Конкуренти** | профил на всеки сайт, който се появява в резултатите: силни страни, слабости, видимост, фрази, при които е уязвим |
| **План за съдържание** | препоръчан тип и обем, заглавие, подтеми, въпроси, термини, schema.org, списък със задачи; ако си задал своя страница — какво ѝ липсва спрямо водещите |
| **Данни и методика** | какво е струвал анализът, откъде идват данните, всички формули и ограничения |

Отчетите се пазят и се свалят като CSV (за Excel), Markdown или JSON.

## Как се използва Jev

Jev не пише текст и не знае какво е на първа страница днес. Той отговаря на **типизирани въпроси** (да/не, избор, скала) с вероятност и степен на сигурност. Затова работата е разделена така:

| Кой | Какво прави |
| --- | --- |
| **SERP доставчик** (Serper или DataForSEO) | казва кой е на коя позиция, свързаните търсения и въпросите „Хората питат също“ |
| **Код** | тегли публичните страници (спазва `robots.txt`) и измерва: заглавия, дължина, FAQ, цени, контакти, schema.org. Смята всички числа, оценки и подредби |
| **Jev** | решава смисловите въпроси: какъв тип страница е, какво намерение обслужва, колко дълбоко и конкретно е съдържанието, показва ли портфолио, отзиви и ясен призив за действие, и дали една свързана фраза изобщо е за твоя бизнес |

Всяка оценка в отчета може да се провери: виждаш какво е отговорил Jev, с каква вероятност и сигурност, и коя част е измерена от кода.

Заради особеностите на Jev:

- въпросите са малки и фокусирани, а състоянието, което получава Jev, е кратко (дългият контекст влошава отговорите);
- инструкциите са на английски (там Jev е най-точен), а съдържанието — на български;
- типът страница и намерението се питат два пъти с обърнат ред на опциите и отговорите се усредняват (Jev леко предпочита първата опция);
- отговорите с ниска сигурност се показват като такива и тежат по-малко в оценките;
- броенето, процентите и подредбата никога не се поверяват на Jev.

## Бърз старт

Нужен е Node.js 22.19 или по-нов.

```bash
npm install
npm run demo        # примерни данни, без ключове → http://localhost:8787
```

Демо режимът показва как изглежда отчетът с измислени сайтове и имитиран Jev. Нищо от него не е истинско.

### Истински анализ

```bash
cp .env.example .env     # попълни ключовете (виж по-долу)
npm run doctor           # проверява ключовете с по една минимална заявка
npm run build
npm start                # → http://localhost:8787
```

Какво трябва да има в `.env`:

1. **`JEV_API_KEY`** — ключът ти за Jev. Ключ от Vercel AI Gateway (започва с `vck_`) се разпознава сам.
2. **Доставчик на Google резултати** — `SERPER_API_KEY` ([serper.dev](https://serper.dev)) или `DATAFORSEO_LOGIN` и `DATAFORSEO_PASSWORD`. DataForSEO дава и месечни търсения за фразите.

Без SERP доставчик платформата работи в **ръчен режим**: въвеждаш адреси на конкурентни страници и те се анализират, но няма автоматично търсене на свързани фрази.

Разработка с презареждане: `npm run dev` (интерфейсът е на http://localhost:5173).

## Как да четеш отчета

- **Оценката на фраза** (0–100) е `100 × релевантност × (0,50·слабост на конкуренцията + 0,20·търговска стойност + 0,15·специфичност + 0,15·обем)`. Тежестите са на едно място в [`src/shared/weights.ts`](src/shared/weights.ts) и се виждат в раздела „Данни и методика“.
- **Бърза победа** — лесна конкуренция и оценка ≥ 52. **Добра възможност** — ≥ 42. **Трудна** — ≥ 28. Под това — **Пропусни**. Без проверен SERP оценката не надхвърля 52.
- **Слабост на конкуренцията** е средната слабост на резултатите с тежест по позиция: резултат е силен, когато е от точния тип страница, посветен е на фразата, заглавието му съвпада, съдържанието е дълбоко и домейнът е доминиращ.
- **Точките за сигурност** до всяка оценка на Jev показват колко е сигурен. Една точка значи „не се доверявай само на това“.
- **Дълбок анализ** на свързана фраза пуска пълния анализ (теглене на страниците) за нея.

## Цена и лимити

Анализът прави много малки заявки към Jev. Формата показва горна граница, а отчетът — реалния брой, токени и приблизителна цена. Според документацията на TypeSafe към момента на писане входните токени струват $0,042 на милион, а изходните са безплатни; цената е в `JEV_PRICE_PER_MTOK`, ако се промени. Повторените SERP заявки и страници се взимат от дисков кеш (`CACHE_TTL_HOURS`) и не се плащат отново.

Горните граници за един анализ (`MAX_SERP_CALLS_PER_RUN`, `MAX_PAGES_PER_RUN`, `MAX_CANDIDATES`) са описани в `.env.example`.

## Сигурност

- Ключовете са само в `.env` (който не влиза в git). `/api/status` и интерфейсът не ги връщат.
- Сървърът слуша само на `127.0.0.1`. Ако зададеш друг `HOST`, **отказва да стартира без `APP_PASSWORD`**.
- Защита от заявки от чужди сайтове (CSRF): задължителен заглавен ред и проверка на `Origin`. Строга `Content-Security-Policy`.
- Обхождането е защитено от SSRF: само публични адреси, проверка на всеки адрес (и при пренасочване), ограничени портове, лимити за време и размер.
- Обхождането е почтено: спазва `robots.txt`, представя се с ясен `User-Agent`, не заобикаля защити и не влиза зад вход.
- Текстът от чужди страници се чисти от скрит текст, скриптове и банери, преди да стигне до Jev. Експортът в CSV е защитен срещу формули в Excel.

## Ограничения

Не ги пропускай:

1. **SERP и DataForSEO адаптерите не са пробвани с жива заявка.** Адресите, параметрите и имената на полетата са сверени с публикуваната документация и схеми на доставчиците, а кодът е тестван с имитирани отговори. Ако някой доставчик върне друг формат, `npm run doctor -- --serp` (една заявка) ще го покаже, преди да изразходваш цял анализ.
2. **Връзката с Jev също е проверена само с имитиран сървър.** Форматът на заявката е проверен през официалния SDK, но първият истински анализ е първата реална проба.
3. **Няма данни за обратни връзки и авторитет на домейна.** Страница със слабо съдържание на много силен домейн може да е трудна за изпреварване, макар отчетът да я показва като лесна. Обърни внимание на „доминация на силни домейни“.
4. **Jev е най-точен на английски.** При български текст сигурността му е по-ниска; отчетът го казва, когато е така.
5. **Оценките са вероятности и ориентир за приоритет**, не гаранция за позиция.
6. **Месечните търсения идват само от DataForSEO** и могат да липсват за редки фрази.
7. **Страници, които се зареждат с JavaScript, се четат само като HTML** и може да изглеждат по-тънки, отколкото са.
8. Предназначена е за един потребител или малък екип: отчетите са JSON файлове в `DATA_DIR`.

## Структура

```
src/shared/   типове, схеми, пазари и тежести — общи за сървъра и интерфейса
src/server/   Hono API · jev/ (клиент и въпроси) · providers/ (SERP, кеш) · crawl/ (теглене и извличане)
              nlp/ (български) · analysis/ (оценки, сигнали, възможности, конкуренти, план) · pipeline/
src/web/      Preact интерфейс (хеш рутер, без външни зависимости за графиките)
scripts/      doctor — проверка на ключовете
tests/        unit и integration тестове
```

## Разработка

```bash
npm test             # всички тестове
npm run typecheck    # TypeScript за сървъра и интерфейса
npm run build        # dist/web (интерфейс) и dist/server.mjs
```

Тестовете не правят външни заявки: Jev и SERP се имитират, а обхождането работи срещу локален сървър.

С Docker:

```bash
docker build -t jev-seo-radar .
docker run --rm -p 8787:8787 --env-file .env -e APP_PASSWORD=избери_парола -v radar-data:/app/data jev-seo-radar
```
